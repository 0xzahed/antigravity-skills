# Requirements Analysis

## Use this skill when
- Writing or reviewing requirements documents, PRDs, or feature specifications
- Decomposing a vague request into concrete, testable requirements
- Running a requirements-gathering session or an inception workshop

## Do not use this skill when
- Implementing already-approved requirements
- Only writing acceptance criteria for an existing story
- The scope is a trivial one-line change

## Instructions
1. Collect stakeholder input and define the problem clearly.
2. Structure requirements into functional, non-functional, and constraint buckets.
3. Find gaps, dependencies, and contradictions across the document.
4. Prioritize using MoSCoW and get sign-off before implementation.
5. Map every requirement to a business goal.
6. Output a requirements matrix with ID, type, description, priority, and status.

## Output Format
- ID | Type | Requirement | Priority | Status | Open Questions

## Common Mistakes
- Inventing requirements the user never asked for
- Writing implementation details instead of behaviors
- Skipping non-functional requirements (performance, security, ops)
