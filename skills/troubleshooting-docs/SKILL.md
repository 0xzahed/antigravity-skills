# Troubleshooting Documentation

## Use this skill when
- Documenting known issues and fixes
- Reducing support and ops load
- Capturing hard-won debugging knowledge

## Do not use this skill when
- General docs (use its own skill)
- Chat debriefs that never get written

## Instructions
1. For each issue: symptom → cause → resolution → prevention.
2. Give copy-paste commands and exact steps.
3. Add decision checks (what to try first, what not to).
4. Tag by area and error text for search.
5. Update after each real incident.
6. Verify steps are current by test-driving them.

## Checklist
- Steps verified
- Searchable symptom phrases
- Date/owner noted

## Output Format
- Issue | symptom | resolution | verified date

## Common Mistakes
- Untested complex steps
- Very specific errors without search tags
- Outdated workarounds lingering
