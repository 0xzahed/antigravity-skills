# Design Patterns

## Use this skill when
- Choosing patterns to solve common design problems
- Refactoring toward proven structures
- Explaining the trade-offs of patterns

## Do not use this skill when
- A simpler idiomatic solution exists
- You are teaching (refer to authoritative sources)

## Instructions
1. Identify the problem before choosing a pattern.
2. Match the pattern to the problem: creation, structure, behavior.
3. Note the pattern trade-offs and alternatives.
4. Ensure the pattern earns its complexity.
5. Prefer language-idiomatic solutions where they replace a pattern.
6. Implement with clear names that reveal pattern intent.

## Output Format
- Pattern | Problem | Implementation | Trade-offs

## Common Mistakes
- Applying patterns for their own sake
- Choosing patterns from memory without verifying fit
